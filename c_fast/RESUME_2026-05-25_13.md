## Core Question

The user is exploring whether DE benefits more from better fitness/data design
than from evolutionary-mechanics tweaks, especially for NN training.

Current conclusion: for ordinary smooth full-domain sine regression, DE can
train small NNs but is not competitive with what gradient descent should do.
The useful research direction is to exploit DE's ability to optimize awkward
fitness objectives, structured/non-differentiable choices, robust losses, and
architecture/search variants.

## Sequence Task

Recurrence:

```text
x[t] = sin(2.5 * x[t-1]) + 0.6 * x[t-2]
```

Input is `[a, b] = [x[t-1], x[t-2]]`; target is `x[t]`.

Important distinction:

- Trajectory data: adjacent windows from one generated path. Easy, but can be
  orbit-fitting.
- Random state pairs: independent samples from a box such as `[-2.5, 2.5]^2`.
  Harder and more honest for function learning.

Domain width:

```text
pair1-mid [-1.5, 1.5]^2:
  test step0 MSE:           0.00565

pair1-2p0 [-2.0, 2.0]^2:
  test step0 MSE:           0.01634

pair1 full [-2.5, 2.5]^2:
  test step0 MSE:           ~0.049
```

So the full-box issue is not just randomness; it is broad state-space coverage.

Multi-output/MTP-style attempts:

- `seq2`, `pair2`, auxiliary heads, duplicate heads: not useful yet.
- Extra output heads increase weight/search dimension and hurt DE.
- Revisit MTP later after improving evaluator speed or model structure.

Population-carrying curriculum:

- Added `DeState` to carry full populations across stages.
- `curriculum`: `pair1-mid -> pair1-2p0 -> pair1`
- `curriculum2`: `pair1-2p0 -> pair1`
- `fixedfull`: same continuation API but trained only on full pair task.

Results:

```text

  final full-box test MSE: 0.04538
```

Conclusion: carrying population works mechanically, but simple central-to-full
