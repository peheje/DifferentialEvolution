# PyTorch DE Performance Note

Commit: `5e481f9` (nn-genann-experiments)

## Optimization

Replaced per-individual Python `_pick_indices()` loop with vectorized numpy
`_pick_all_indices()`. The old code called `_pick_indices()` once per population
member per generation (e.g. 768 calls × 12000 gens = 9.2M Python function calls
with per-call rejection sampling). The new code generates all [P, n_pick]
indices in a single numpy call per generation, fixing collisions vectorized.

## Speed vs C baseline

PyTorch CUDA pair5-hard 1-run (17.2s) vs C OpenMP pair5-hard 1-run (~66s):
**~3.9x faster**. Pair1 (49 weights) is only modestly faster (5.9s vs ~7s)
due to GPU kernel launch overhead on tiny matmuls.

This is a speed comparison only — PyTorch uses independent data/RNG draws
and torch.sigmoid (C uses genann cached-sigmoid LUT). Result quality is
not directly comparable without fixture export.

## Current bottleneck

- **mutation/crossover (28%)**: numpy→torch tensor transfers for
  crossover random masks — candidate for GPU-side generation
